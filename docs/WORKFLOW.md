# 制作与返修流程

## 1. 素材与约束

本案例将洛天依画面角色替换为初音未来。高清源为 `project/upload/175348148-1-208.mp4`；`sources/` 还保留最早的低清源与原伴奏。原镜头顺序、字幕、署名、场景、道具、鸟群与唱声沿用，不把换人物扩成改编故事或换声。

用户提供的完整技能说明在 `tools/pv-character-replacement/skills/pv-character-replacement/`。它提供分析时序、人物比例、图层、提示词、后期、验收与交付规范；其命令行工具的额外依赖在 `tools/pv-character-replacement/requirements.txt`，不属于仅重合成所需的根依赖。

## 2. 分析原片与曝光

从高清源定位镜头边界、源姿态及动作曝光，保存源帧与姿态映射。`project/work_hd/refs/` 和 `project/work_repair/refs/` 是合成所用参考；时序以 `final_exposures.json`、`pier_exposures.json`、`pier_states.json` 为准。

码头是 A/B/C 三张原姿态组成八次曝光，不能用两稿或摄影机平移代替。原曝光半开帧区间为 A1982–2006、B2006–2024、C2024–2039、B2039–2057、A2057–2075、B2075–2093、C2093–2108、B2108–2177。

## 3. 绘稿与采用

保持青绿双马尾、铅笔线稿、白色连帽服装及源姿态比例。需要新绘稿时，用真实图像生成或用户提供绘稿，保存提示词和参考角色；旧生成记录在 `work_hd/assets/*.json` 与 `work_repair/assets/*.json`，封面实际提示词在 `cover/`。

目前采用 34 张独立人物稿，其中返修新增 4 张；采用路径以 `project/work_repair/delivery_manifest.json` 为唯一当前映射。`bird_crown` 复用 `water_birds`。`assets/history/` 保存被采用与未采用的历史图，避免误用旧稿覆盖返修。

## 4. 图层归属与合成

修复逻辑在 `compose_repair.py`，依赖旧高清合成器 `compose_hd.py`。遮罩在 `masks.json`，决定头发、头部、杯子、水面等像素归属；它们是图层遮罩，不是用几何图形绘制角色。

头发归属要覆盖真实青绿轮廓，不能用固定矩形切断发束。桌上杯子按实际轮廓作为前景；水面与鸟群独立恢复。1:09 头部浮在水外；1:23–1:30 使用真实 A/B/C 姿态和源曝光，不能漏替换。需要浸水的尾发沿水面曲线应用水层，脖子、玻璃与衣领边缘必须保持连续。

当前返修重合成 1704 帧，半开帧区间：`[342,762)`、`[898,1038)`、`[1574,1710)`、`[1982,2177)`、`[2266,2405)`、`[2544,2678)`、`[4184,4456)`、`[5006,5274)`。区间外从已接受的高清 Miku 基线读取，再整片编码。不要因再次有损编码声称与旧基线像素完全一致。

## 6. 输出与验收

`continue_local.py render` 合成最新修正版，`compare` 生成对照，`review` 生成编码后静帧板，`verify` 全片解码、核对帧数和 AAC。三个修复交付视频已放入 `project/output_repair/`，可以直接执行校验，无需先重新渲染。

主片 1920×1080、24fps、H.264 High、yuv420p、CRF16；AAC 从原片复制。主片与全片对照 5422 帧；九处局部对照 1488 帧、62秒，其剪辑音频重新 AAC 编码。静帧检查后还应实际原速播放检查节奏与运动；此前的原始交付没有完成这一步，存档不能被改写成做过。

## 7. 仓库交接

把采用稿、提示词、遮罩、曝光、源帧、成片和验收证据一同提交。`verify_repository.py` 校验仓库快照，`continue_local.py check` 校验合成准备状态。GitHub 仓库的大媒体通过原始字节分块提交；运行 `prepare_media.py` 自动还原，源码和流程文档通过普通 Git 提交。

旧交接原文留在 `docs/history/`。其中旧目录名与新目录的对应关系在 `repository_conversion.json`；旧工程 ZIP 已展开为 `project/`，未保留重复的 120 MB 工程压缩文件，内容完整保留。
